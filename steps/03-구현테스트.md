# 03 · Phase 1 구현과 테스트

**목표**: `service-prd.md`에 적힌 Phase 1만 구현하고 참가자가 핵심 시나리오를 직접 확인한다.

## 구현 전

1. `service-prd.md`를 읽는다.
2. 현재 파일과 `git status`를 확인한다.
3. 구현할 항목과 건드릴 파일을 짧게 설명한다.
4. 시크릿·개인정보·회사 자료가 입력 파일에 없는지 확인한다.

## 구현

- 실제 서비스는 루트 경로 `/`에 만든다.
- PRD의 화면 원칙, 버튼 이름, 성공 기준을 따른다.
- `data/`의 TXT·JSON·CSV 또는 코드 안의 더미 데이터만 사용한다.
- Phase 2, 로그인, DB, 외부 API, 크롤링, 외부 AI는 추가하지 않는다.
- 필요한 버튼과 입력은 실제로 동작하게 한다.
- 구현이 끝나면 `npm run build`를 실행한다.

## 직접 테스트

로컬 서버의 실제 URL을 알려주고 참가자가 PRD의 핵심 시나리오를 직접 실행하게 한다. 실패하거나 불편한 부분은 한 번에 하나씩 수정한 뒤 다시 확인한다.

## Git 세이브 포인트

핵심 시나리오와 빌드가 정상이고 참가자가 결과를 확인하면 다음을 수행한다.

1. `git status`와 변경 파일을 보여준다.
2. `.env*`, 키, 토큰, 개인정보, 고객 데이터가 포함되지 않았는지 확인한다.
3. 참가자 동의를 받은 뒤 정상 동작 상태를 커밋한다.

원격 저장소로 push하지 않는다.

**참가자가 직접 할 일**: 핵심 시나리오를 실행하고 고칠 점을 구체적인 문장으로 요청한다.

**완료 신호**: Phase 1과 빌드가 정상이고 Git 세이브 포인트가 만들어진다.

**PROGRESS 기록**: Phase 1, 최종 빌드, Git 세이브 포인트 상태를 적고 03 단계를 완료한다.
