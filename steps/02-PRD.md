# 02 · PRD 작성

**목표**: `draft.md`를 실제 구현 기준인 `service-prd.md`로 발전시킨다.

`draft.md`를 읽고 부족한 내용만 최대 3개 질문한다. 질문은 한 번에 하나씩 한다. 답을 바탕으로 다음 내용을 담은 `service-prd.md`를 작성한다.

1. 서비스 한 줄 설명
2. 사용자와 해결할 문제
3. Phase 1 핵심 시나리오
4. 화면 1~2개의 정보 순서와 버튼 이름
5. 사용할 더미 데이터와 파일 위치
6. 성공 기준과 직접 테스트할 항목
7. 수업 후 과제

## 범위 규칙

- Phase 1은 70분 안에 만들고 테스트할 수 있는 크기로 제한한다.
- DB 저장, 로그인, 결제, 외부 API, 크롤링, 외부 AI 호출은 제외한다.
- 소개 페이지, 별도 랜딩 페이지, `info.md`, 별도 디자인 기획 문서는 만들지 않는다. 다음 구현 단계에서 Refero Styles의 참고 규칙을 담은 `DESIGN.md` 하나만 선택적으로 추가할 수 있다.
- 필요한 경우 새로고침하면 입력이 초기화될 수 있음을 화면에 알린다.

문서를 보여주고 참가자가 범위와 성공 기준을 확인하면 멈춘다. 아직 구현하지 않는다.

**참가자가 직접 할 일**: 질문에 답하고 Phase 1 범위를 승인한다.

**완료 신호**: `service-prd.md`가 저장되고 참가자가 승인한다.

**PROGRESS 기록**: 서비스 이름과 Phase 1 핵심 시나리오를 적고 02 단계를 완료한다.
